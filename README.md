# SOP2Program

**English** | [简体中文](README.zh-CN.md)

Compile laboratory standard operating procedures (SOPs) into typed action programs, check them with a symbolic verifier, and repair them under source-text constraints. Replay accepted programs using annotated entity chains to check whether verifier acceptance also holds when entity identities are resolved from the annotations.

This repository contains the complete experimental code for *Identity-sensitive verification and learned repair for language-model compilation of laboratory protocols* (submitted to Applied Intelligence). The code files are **byte-for-byte identical** to those used to produce the paper's results (see [`CODE_SHA256.json`](CODE_SHA256.json)). Some scripts fingerprint source files to ensure consistency when resuming runs, so **do not modify existing `.py` files**; use new scripts or output directories for changes.

## Main findings (reported in the paper)

| Experiment | Result |
|---|---|
| Five-fold X-WLP evaluation, 276 protocols, fine-tuned 14B compiler | First-pass compilation confirms 97 protocols → deterministic repair 142 → trained cascade 188 |
| Identity gap | 15.5–22.2% of repaired programs accepted by the string verifier fail entity-chain replay |
| Controlled comparison (generation ceiling 8, no fallback model) | Producer feedback P confirms 180; N/O/U/C controls confirm 142–149 |
| Three training seeds | P confirms 180/185/170 (mean 178.3, SD 7.6); D averages 147.3; P loses no protocols confirmed by D in any seed |
| External baselines on the same backbone (base Qwen3-14B) | CRITIC-style refinement confirms 158, CLAIRify-style refinement 160; P performs significantly better (Holm-adjusted p=0.0025) |
| External baselines using an API model (deepseek-flash) | Self-Refine confirms 167, CRITIC 186, CLAIRify 189; differences from P are not significant, while CLAIRify uses 11 times P's output tokens |
| Second corpus: ChEMU (225 test snippets) | Deterministic repair raises confirmations from 71 → 150 (79 gains, 0 losses); 28–29% of acceptances under every repair method fail replay; learned and API-based repair add at most 8 confirmations |

“Confirmed” means passing **both** the full string verifier **and** state replay using annotated entity chains. See [`docs/architecture.md`](docs/architecture.md) for detailed definitions.

## Environment

- Python 3.13. The paper's experiments used native Windows with CUDA 12.8, PyTorch 2.8.0, Transformers 4.57.6, and PEFT 0.18.1.
- GPU: one card with approximately 24 GB of VRAM (the paper used an RTX 5090 D v2). Compilation evaluation with the 14B model at batch size 32 requires approximately 23 GB. On Windows, insufficient VRAM can cause a fallback to system memory, slowing runs by several times or more than an order of magnitude; see the runtime notes in [`docs/reproduce.md`](docs/reproduce.md).
- For CPU audits and unit tests only, use `requirements-cpu.txt`.

```powershell
# CPU: unit tests and audits (install the CPU build of torch==2.8.0 first)
python -m pip install -r requirements-cpu.txt
python -X utf8 -m pytest tests -q        # Without data or models: 92 passed, 9 skipped
# With the paper's archived data and results (after extracting Online Resource 1),
# recompute all reported numbers with one command
python -X utf8 paper/applied_intelligence/tools/run_audits.py

# GPU: install torch==2.8.0 for your CUDA version first, then the remaining dependencies
python -m pip install -r requirements-gpu.txt
```

On Windows, set `$env:PYTHONUTF8='1'` and use `-X utf8` for Python commands.

## Quick start: compile your own SOP

```powershell
python -X utf8 scripts/compile_sop.py --input examples/lifecycle.txt `
    --anchors examples/lifecycle_anchors.json --inventory examples/empty_inventory.json `
    --adapter results/lora3b_full/adapter --rules results/symbolic/full_rules.json `
    --output results/lifecycle_workflow.json
```

Inputs are UTF-8 text, action spans `{start,end}` in execution order (with an exclusive `end` offset), and an initial material inventory. The output includes the program, step-by-step states, raw model output, structured violations, and a PASS/REPAIRED/REVIEW status. Train the adapter and induce the rules first; see [`docs/reproduce.md`](docs/reproduce.md).

## Scope and limitations

- Action anchors and the initial material inventory come from annotations. This is a component-level compilation task, rather than end-to-end SOP understanding.
- “Confirmed” checks consistency with the projected state model; it does not establish that an experiment is executable in a real laboratory. This repository does not connect to laboratory equipment.
- Entity-chain resolution is heuristic, and replay failures provide a diagnostic estimate.
- The paper is the authoritative source for the study's limitations and interpretation boundaries.
